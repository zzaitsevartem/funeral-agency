# Фаворит

Витрина и админка находятся в `frontend/`, API Express и схема Prisma — в `backend/`. Nginx проксирует витрину, API и загруженные изображения через один адрес.

## Локальный запуск

Compose читает `.env` из корня. Для новой установки скопируйте `.env.example` в `.env` и заполните переменные доступа по инструкции ниже. Затем запустите сервисы.

```sh
docker compose up --build --wait
curl --fail http://127.0.0.1:8080/health
```

- Витрина доступна на `http://127.0.0.1:8080/`.
- На старте API применяет миграции и заполняет базовые категории и способы доставки. `SEED_DEMO=true` добавляет демонстрационный товар.
- `PAYMENT_MODE=offline` оставляет офлайн-оплату. Для тестового стенда `PAYMENT_MODE=test` подключает симулятор результата оплаты. Симулятор не принимает деньги.

PostgreSQL хранит каталог, заказы и платежи. Redis хранит корзины и сессии с ограниченным сроком жизни. База, Redis и загрузки сохраняются в локальных томах после `docker compose down`.

## Первый вход в админку

1. Откройте локальный `.env` в редакторе. В этом проекте случайный `ADMIN_ENTRY_SLUG`, ключ `ADMIN_JWT_SECRET` и одноразовый `ADMIN_BOOTSTRAP_TOKEN` уже записаны в файл.
2. Откройте `http://127.0.0.1:8080/<ADMIN_ENTRY_SLUG>/register`, подставив значение переменной без угловых скобок. Введите свой email, пароль из 15 или более символов и значение `ADMIN_BOOTSTRAP_TOKEN` в поле «Код регистрации».
3. Войдите с выбранным email и паролем на `http://127.0.0.1:8080/<ADMIN_ENTRY_SLUG>`. После входа откроется `/admin`. После первой регистрации создание других аккаунтов через форму закрывается.
4. После выхода или окончания сессии откройте `/admin` и войдите со своим email и паролем.

На новой установке используйте `a-` и 32 случайных шестнадцатеричных символа для адреса. Для ключа подписи JWT и кода регистрации сгенерируйте два разных значения командой `openssl rand -hex 32`. `ADMIN_ORIGIN` должен совпадать с адресом сайта, включая схему и порт. Для публичного размещения используйте HTTPS и храните ключ и код вне репозитория.

После регистрации пароль хранится как хеш в PostgreSQL. JWT приходит только в HttpOnly cookie. Выход завершает сессию в Redis, поэтому прежняя cookie больше не даёт доступ.

## Логи и состояние

`/health` проверяет соединения с PostgreSQL и Redis. Логи Nginx и API в JSON используют общий идентификатор запроса. Посмотреть логи можно командой `docker compose logs -f nginx backend`. Порты меняются переменными `APP_PORT` и `BACKEND_PORT`.

Команды браузерной проверки описаны в [e2e/README.md](e2e/README.md).
